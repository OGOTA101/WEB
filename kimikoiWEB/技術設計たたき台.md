## Unityバージョン

**Unity 6 LTS（6000.0.x）** を採用する。

Unity 6は2024年末にリリースされた現行メジャーバージョンであり、LTSブランチは2年以上のサポートが保証される。  
モック開発からフル開発まで同一バージョンを維持することを前提とする。

- Unityライセンス：Personal（無料）✅
- アップグレード方針：LTSのマイナーアップデートのみ追随する。メジャーアップグレードはフル開発フェーズ開始前に1度だけ行うか否かを判断する。

## レンダリングパイプライン

**URP（Universal Render Pipeline）2D Renderer** を採用する。

本作は仮想デスクトップUIとSpine立ち絵が主体の2D構成であり、3Dレンダリングは不要。  
URPを選ぶ理由は以下のとおり。

- グリッチ・ノイズシェーダーをShader Graphで実装できる
- Post-processingが標準統合されており追加パッケージ不要
- Built-inに比べてモバイル・Steam Deck等への後日移植が容易
- Unity 6世代においてBuilt-inの新機能開発は事実上停止している

> ⚠️ **画像アセットのパイプラインは別途決定済み** とのことのため、テクスチャ圧縮設定・インポート設定のルール合わせは美術担当と要確認。

## シーン設計

### シーン構成

| シーン名 | 役割 |
|---|---|
| Boot | 初期化・ロゴ表示（Additive非使用。最初に必ずここを経由） |
| Title | タイトル画面・CONFIG・EXIT |
| Desktop | ゲーム本体（仮想デスクトップ全体）。常駐シーン |
| KimikoiApp | 作中ADV（キミコイアプリ）。Desktopにてアドレス指定でAdditive Load |
| Ending | エンディング画面 |

Desktopシーンを主軸として、各アプリウィンドウはPrefab/GameObjectの表示切替で管理する。  
シーン遷移ではなくウィンドウの開閉が基本操作であるため、シーン数は最小限に保つ。

### 管理クラス設計方針

- **GameManager**（シングルトン）：ゲーム全体のフローとフェーズ管理
- **WindowManager**：ウィンドウのOpen/Close/Minimize/Drag管理。レイヤー順（SiblingIndex）制御
- **ParameterManager**：妹パラメーター4種の保持・増減・イベント通知
- **ScenarioManager**：ADVシナリオのCSV読み込み・テキスト送り・選択肢制御
- **SoundManager**：BGM/SEのAudioMixer経由再生。音量設定の即時反映
- **SaveManager**：設定値とゲーム進行データの読み書き

## セーブシステム

保存すべきデータは以下の2種類。

### 設定データ（Setting）

音量・解像度などの環境設定。**PlayerPrefs** で保存する（軽量、PC再起動をまたいで保持される）。

### ゲーム進行データ（Save）

パラメーター値・フラグ・シナリオ進行状況など。**Easy Save 3** または **JSONファイル直書き** を採用する。

> ⚠️ モック段階ではフラグ数が少ないため、JSON直書きで実装し、フル開発時にEasy Save 3へ移行するかを判断する。  
> ⚠️ セーブデータの暗号化要否を要確認。Steamのオフライン改造を許容するかどうかの設計判断が必要。

## UI システム

**uGUI（Canvas + RectTransform）** を採用する。UI Toolkitは採用しない。

選定理由は以下のとおり。

- ウィンドウのDrag移動・SiblingIndex操作はuGUIのほうが制御しやすい
- DOTweenのUI対応がuGUIを前提としている
- UI Toolkitはゲームプレイ向けUIの成熟度がuGUIに比べて低い（Unity 6時点）
- チームの習熟度コストを考慮

### Canvas構成

| Canvas名 | Sort Order | 用途 |
|---|---|---|
| DesktopCanvas | 0 | 仮想デスクトップ背景・Spine立ち絵 |
| WindowCanvas | 10 | 各アプリウィンドウ（Z順をSiblingIndexで制御） |
| TaskbarCanvas | 20 | タスクバー（常時最前面） |
| OverlayCanvas | 30 | ダイアログ・スキンシップパート（全要素の前面） |

## オーディオ

AudioMixerを使用し、マスター・BGM・SEの3チャンネル構成とする。

| チャンネル | 用途 |
|---|---|
| Master | 全体音量（ミュートボタン等で使用） |
| BGM | ループBGM（タイトル・デスクトップ等） |
| SE | UI操作音・Spineアクション音 |

- BGM音量変更は AudioMixer の exposed parameter 経由で即時反映する
- SE音量変更時はプレビュー用SEを1回再生してフィードバックを与える
- BGMのクロスフェードはDOTweenのAudioSource.volume補間で実装する

## グリッチ・ノイズシェーダー

8以上の画面でグリッチUI差替が要件になっている。Shader Graphで汎用グリッチエフェクトを1本作成し、MaterialPropertyBlock経由でパラメーター調整できる設計にする。

- 対象：仮想デスクトップ・妹パラメーター・タスクバー・LIME・Googru・タスクマネージャーなど
- 実装方針：UIへの適用はRaw Image + Render Textureを経由するか、UI Material差替で対応
- ノイズテクスチャ：Perlinノイズ or Shader内生成

> ⚠️ Render Textureを使う場合はメモリ使用量に注意。解像度を固定（256×256程度）にすることを推奨。

## Spine統合

Spine Unity Runtime（4.x系）を採用する。

| 使用箇所 | 内容 |
|---|---|
| 仮想デスクトップ | 妹立ち絵の常駐表示・待機アニメーション |
| 常駐呪いの妹 | ゲーム全体を通じた監視・リアクション演出 |
| スキンシップパート | 5コマンド（なでる・たたく・ハグ・くすぐる・終了）ごとのアニメーション |

- SkeletonGraphicコンポーネントを使用してuGUI Canvas上に描画する
- アニメーション切り替えはSetAnimation / AddAnimationで管理
- Spineライセンスは別途必要（Esoteric Software社）

## 入力システム

**New Input System**（com.unity.inputsystem）を採用する。

- マウスクリック・ホバー検出はEventSystem + IPointerHandler で処理
- カスタムカーソルはCursor.SetCursor()で実装（テクスチャ差替方式）
- キーボードショートカットはInputActionAssetで管理し、将来のキーコンフィグ対応を考慮

## アセット管理

### フォルダ構成（Assets以下）

```
Assets/
  _Scenes/         # シーンファイル
  Scripts/         # C#スクリプト（機能別サブフォルダ）
  Prefabs/         # Prefab（Window/UI/Character別）
  UI/              # uGUI Spriteアトラス・UIテクスチャ
  Characters/      # Spineデータ（atlas, json, png）
  Scenarios/       # シナリオCSV・Googruページデータ
  Audio/
    BGM/
    SE/
  Shaders/         # ShaderGraphアセット
  Materials/       # Materialアセット
  Fonts/           # TMPフォントアセット（PixelMplus12・源暎エムゴv2）
  StreamingAssets/ # 実行時に動的に読み込む外部データ（シナリオCSV等）
```

### アセットロード方針

Addressablesは使用しない。規模・チーム規模的にオーバーエンジニアリングになるため。  
シナリオCSV・Googruページデータは StreamingAssets に配置し、実行時にFile.ReadAllTextで読み込む（データ入力担当者がUnityを開かずに編集できる）。

- ホスティング：GitHub（Privateリポジトリ）✅
