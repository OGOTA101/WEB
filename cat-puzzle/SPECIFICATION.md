# 仕様書: 猫つながりパズル「ねこリン」 (Neko Link Puzzle)

## 1. プロジェクト概要

### コンセプト
**「つながると、猫になる。」**
クラシックな「さめがめ（SameGame）」のルールをベースに、つながったブロックが**一体の猫**のようなビジュアルに変化するパズルゲーム。
ブロックをつなげればつなげるほど、長く、大きな猫の形になる視覚的な楽しさを重視する。

### ターゲットプラットフォーム
- **Webブラウザ** (PC / Data Friendly)
- **Viewport**: 9:16 (モバイル縦長) またはレスポンシブ

---

## 2. ゲームメカニクス

### 基本ルール (Base Rules)
1.  **盤面**: 格子状に配置された多色のブロック。
2.  **操作**: 2つ以上つながっている同色のブロックをクリック/タップ。
3.  **消去**: タップされたブロック群は消滅し、スコア加算。
4.  **重力**: 消えたブロックの上のブロックは落下して隙間を埋める。
5.  **スライド**: 縦列が全て消えた場合、右側の列が左に詰める（一般的なさめがめルール）。
6.  **終了条件**: 消せるブロックがなくなった時点で終了。

### スコア計算
- 基本式: `(消した数 - 2) ^ 2` などの指数関数的増加を採用し、まとめて消す爽快感を推奨。

### 難易度設定
- **Color Count**: 3色からスタートし、最大7色まで増加。
- **Grid Size**: 難易度に応じて変動（例: 10x10 〜 15x20）。

## 3. ビジュアル仕様 (Visual Specification)

本ゲームの核心部分。単なる色付きブロックではなく、連結状態に応じて「猫のパーツ」として描画する。

### A. 猫の構造ロジック (Cat Structure Logic)

連結した同一色のブロック群（クラスター）全体を解析し、四肢と頭の位置を決定する。
個々のブロックのローカルな接続状況だけでなく、**クラスター内での相対位置**が重要となる。

#### 1. 各パーツの特定アルゴリズム
クラスターに含まれる全ブロックの座標 `(x, y)` を基に、以下の優先順位で役職（Role）を決定する。
※ 座標系は 左上が (0,0)、右下に行くほど値が増えるとする。

1.  **Head (頭・顔)**:
    - 条件: **一番上** (`Min Y`) のブロック。
    - 複数ある場合: その中で **一番左** (`Min X`) のもの。
    - 常に1つだけ存在する。

2.  **Hand (手/前足)**:
    - 条件: **一番下** (`Max Y`) のブロック。
    - 複数ある場合: その中で **一番左** (`Min X`) のもの。
    - 「🐈」のポーズの前足に相当。

3.  **Foot (足/後ろ足)**:
    - 条件: **一番下** (`Max Y`) のブロック。
    - 複数ある場合: その中で **一番右** (`Max X`) のもの。
    - 「🐈」のポーズの後ろ足に相当。
    - ※ `Hand` と `Foot` が同一ブロックになる場合（幅1の場合）、そのブロックは「手足両方（座りポーズ）」を持つ。

4.  **Tail (尻尾)**:
    - 条件: **一番右** (`Max X`) のブロック。
    - 複数ある場合: その中で **一番上** (`Min Y`) のもの（尻尾を立てているイメージ）。
    - ※ `Foot` と座標が被る場合もある。

#### 2. パーツの描画優先順位
1つのブロックが複数の役職を持つ場合（例: 1x1のブロックは 頭+手+足+尻尾）、すべてのパーツを描画する（合成する）。
- 例: 1x1ブロック → 顔があり、下に手足があり、右上に尻尾がある（丸まった猫）。

### B. パーツ詳細リスト (Parts List)

各ブロックは基本「胴体（毛皮）」であり、役職フラグに応じて装飾パーツを重ねて描画する。

| 役職 (Role) | 座標条件 (概要) | ビジュアル・装飾 |
|:---|:---|:---|
| **Head (顔)** | `Min Y` > `Min X` | **正面を向いた猫の顔**。耳付き。 |
| **Hand (左手)** | `Max Y` > `Min X` | ブロックの左下付近に**前足**を描画。 |
| **Foot (右足)** | `Max Y` > `Max X` | ブロックの右下付近に**後ろ足**を描画。 |
| **Tail (尻尾)** | `Max X` > `Min Y` | ブロックの右端から**尻尾**が生える（右上へ跳ねる等）。 |
| **Body (胴体)** | 上記以外、または上記の下地 | 毛並みのテクスチャ。隣接ブロックとは境界線なしで結合。 |

**補足イメージ:**
- 🐈 (横向き猫) のシルエットをブロックで表現する。
- どんなにいびつな形でも、論理的な「左上」「左下」「右下」「右端」にパーツを割り振ることで、なんとなく猫に見えるようにする。

### C. アートスタイル
- **視点**: 基本は正面顔だが、体は横向き（🐈）のような構成。
- **トーン**: にょきにょき/ぷよぷよ系の結合 + 猫パーツの付与。

## 4. 実装計画

### Step 1: ベースゲームの実装
- グリッド生成、クリック判定、連結ロジック、削除・落下処理。

### Step 2: 連結判定ロジックの実装
- 各ブロックに対し、毎フレーム（あるいは盤面更新時）に `ConnectivityFlag` (U, D, L, R) を計算。
- `IsHead` フラグの計算。

### Step 3: レンダリング実装
- HTML5 Canvas または DOMベースでの描画。
- 画像アセットの動的生成（または`generate_image`ツールによる作成）。
- ※初期段階では、CSSの `border-radius` や `::before/::after` を駆使したプロシージャル生成も検討可能だが、画像の方がリッチになる。今回は画像アセット生成を前提とする。

### Step 4: UI構築
- スコア、リセットボタン、難易度選択。
