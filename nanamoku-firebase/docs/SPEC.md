# ナナモク ゲーム仕様 v0.1

作成日: 2026-04-24

## 目的

「普通の五目並べの読み合い」に、7人対戦、30x30盤面、デッキ、ガチャ、石を消費するスキルを足した、ソーシャルゲーム風の変則7目並べを作る。

遊びとしては、1手の重さを残しつつ、カードによって盤面が大きく動く対戦ゲームにする。ブラウザで遊べて、Firebase Hostingで配信し、Firestoreでリアルタイム同期する。

## 対応モード

| モード | 内容 |
| --- | --- |
| オンライン対戦 | 2から7人まで同じ部屋で対戦する |
| CPU対戦 | 1人でCPUを1から6体まで追加して遊ぶ |
| 混合対戦 | 人間プレイヤーとCPUを混ぜて最大7席まで遊ぶ |
| ルーム対戦 | ルームコードまたはURL共有で参加する |
| 公開マッチ | 将来の拡張。待機中の部屋に参加できる |

## 基本ルール

| 項目 | 仕様 |
| --- | --- |
| 盤面 | 30x30 |
| セル座標 | x: 0から29、y: 0から29 |
| 最大人数 | 7人 |
| 勝利条件 | 自分の石を縦、横、斜めのいずれかで7個以上連続させる |
| 通常行動 | 自分のターンに空きセルへ石を1個置く |
| カード行動 | 通常行動の前に1枚まで使用できる |
| カードコスト | 自分の盤上石の除去を基本に、カードごとに除去条件、通常行動放棄、次ターン制約などを持つ |
| 引き分け | 全セルが埋まり、勝者がいない場合 |
| 観戦 | 将来拡張。初期実装では非対応でもよい |

7個以上で勝利にする。カード効果で8個以上の長い列になった場合も勝利とする。

## プレイヤーカラー

2人対戦では、1番席を黒、2番席を白にする。3人目以降は以下の順に割り当てる。

| 席 | 色名 | UI色 |
| --- | --- | --- |
| 1 | 黒 | #171717 |
| 2 | 白 | #f7f2e8 |
| 3 | 赤 | #e94b5f |
| 4 | 青 | #2f7df6 |
| 5 | 緑 | #31b76a |
| 6 | 紫 | #8b5cf6 |
| 7 | 金 | #d89a1c |

白石は盤面背景と混ざらないように、細い外枠と影を付ける。

## ターン進行

1. 現在プレイヤーがターン開始。
2. 未使用カードがあれば1枚まで発動できる。
3. カードを使う場合、カードごとのコストを支払う。基本は自分の石の除去だが、孤立石、連続石、端石、通常行動放棄などの条件がある。
4. カード効果を解決する。
5. カードに行動放棄がなければ、通常行動として石を1個置く。
6. 勝利判定を行う。
7. 勝者がいなければ次のプレイヤーへターンを渡す。

カード効果だけで7個以上が成立した場合も勝利する。カード発動後に勝利していた場合、通常行動を待たずにゲーム終了にしてよい。

## デッキ仕様

| 項目 | 仕様 |
| --- | --- |
| 持ち込み枚数 | 7枚 |
| 通常カード | 4枚 |
| 強カード | 2枚 |
| 最強カード | 1枚 |
| 使用制限 | 各カードは1試合に1回だけ使用 |
| 重複 | 初期案では同名カードは1デッキ1枚まで |
| 表示 | 試合中は7枚すべてが手札として見える |

ガチャでカードを入手し、試合前にデッキを編集する。初期実装では全カード解放状態のデバッグデッキを用意し、ガチャは後続フェーズで入れてもよい。

## カード共通ルール

| 項目 | 仕様 |
| --- | --- |
| 発動タイミング | 自分のターンの通常行動前 |
| 発動回数 | 1ターン1枚まで |
| コスト支払い | 自分の盤上石の除去を基本に、孤立石指定、連続石指定、端石指定、通常行動放棄、次ターン制約などを組み合わせる |
| 対象セル | カードごとに制限 |
| 勝利判定 | カード効果解決後と通常行動後に行う |
| 不正操作 | Functions側で最終検証する |

カードの「起点」は、原則としてコストとして除去した自分の石の座標を指す。複数個を除去するカードは、いずれかの起点から条件を満たせばよい。石を除去しないカードは、カードごとに起点なし、または対象セル指定として扱う。

低コストカードの一部は、7連に直接つながらない孤立石を複数置ける。これは次ターン以降のカードコストを作るための資源札として扱い、置いた直後に勝利ラインを作れない制限を持つ。

## CPU仕様

| 難易度 | 方針 |
| --- | --- |
| Easy | 空きセルから候補を選び、短い連結やランダム性を優先する |
| Normal | 自分の伸び、相手の脅威、中央寄り、カード使用価値をスコアリングする |
| Hard | 重要セルだけを候補化し、2手から3手先の脅威、7連の形成、複数人の妨害を評価する |

30x30全探索は重いので、CPUは既存石から一定距離内の候補セルだけを見る。Hardでもブラウザが固まらないように、Web Workerで思考する。

## UI要件

| 画面 | 内容 |
| --- | --- |
| タイトル | CPU戦、ルーム作成、ルーム参加、デッキ編集、ガチャへ移動 |
| ルーム待機 | 参加者、色、CPU追加、準備状態、ルームURLを表示 |
| 対戦画面 | 30x30盤面、カード7枚、ターン、プレイヤー一覧、ログを表示 |
| デッキ編集 | 所持カードから通常4、強2、最強1を選ぶ |
| ガチャ | 1回、10回、排出カード演出、所持数更新 |
| 結果 | 勝者、リプレイ用ログ、再戦、退出 |

盤面はCanvasで描画し、HUDとメニューはDOMで作る。30x30でもスマホで触れるように、ズーム、パン、ミニマップを用意する。

## 技術方針

| 領域 | 方針 |
| --- | --- |
| フロントエンド | Vite + TypeScript |
| 描画 | Canvas 2D |
| UI | DOM/CSS、必要に応じて軽量コンポーネント化 |
| 状態管理 | シリアライズ可能なゲーム状態を中心にする |
| オンライン | Firebase Auth + Cloud Firestore |
| 不正対策 | Cloud Functionsで着手とカード効果を検証 |
| テスト | ルールのユニットテスト、Playwrightで画面確認 |

ゲーム状態は描画から分離する。Canvasは見た目だけを担当し、勝利判定、カード効果、CPU思考は `src/game` 側で完結させる。
